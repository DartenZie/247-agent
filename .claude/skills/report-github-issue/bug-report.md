# Bug report

## Title

Name the affected behavior and its symptom, for example:
`Upload fails for PDFs larger than 10 MB`.

## Writing guidance

Describe observable behavior from the user's perspective. Use present tense for
the reproduction scenario. Keep proposed fixes, speculative root causes, code
pointers, and investigation notes out of the report. If the bug has already been
fixed, describe the affected version or historical scenario accurately rather
than implying a verified current failure.

Include prerequisites in the numbered reproduction steps when needed. Record
frequency as always, intermittent, observed once, or a measured rate supported by
the evidence. Include relevant app version, deployment, OS, browser, or
configuration in the environment. The current checkout and local machine are not
evidence of where the user encountered the bug; confirm applicability before
using their details.

Evidence is optional. Include supplied screenshots, exact error messages, or
relevant log excerpts when useful. Exclude secrets and unnecessary personal data.

## Body template

```markdown
### Summary

<1–3 sentences describing the problem>

### Steps to reproduce

1. <Prerequisite or first action>
2. <Next action, continuing as needed>

### Expected behavior

<What should happen>

### Actual behavior

<What happens in the reported scenario>

### Frequency

<How often the problem occurs, with any known conditions>

### Environment

<Relevant versions, deployment, platform, and configuration>

### Evidence

<Optional screenshots, error messages, or relevant logs>
```
