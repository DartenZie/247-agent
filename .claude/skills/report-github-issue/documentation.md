# Documentation

## Title

Name the documentation change and its topic, for example:
`Document the upload size limit`.

## Writing guidance

Identify what readers cannot understand or accomplish with the current guidance.
Link to the affected page or provide its repository path and relevant section.
For new documentation, identify the proposed location when known and mark it as
proposed. File paths belong in documentation issues because they identify the
material to change.

State what the documentation should explain or correct. Keep simple corrections
short; a typo report does not need a business case.

## Body template

```markdown
### Problem

<What is wrong, unclear, outdated, or missing>

### Location

<Affected link or file path and section, or proposed location for new documentation>

### Requested change

<What the documentation should explain or correct>
```
